When NOT to use an LLM: the decision gate that saves tokens and latency

Deterministic, decision, or generation: the 3 execution tiers to decide when to call a model and stop paying token costs for tasks simple logic can solve.

AC
Alfredo R. Câmara Creator of AI Second Brain
📅 October 22, 2026 · ⚡ AI Decision Gate & JEV

Many developers still believe that “adding AI” to their software product simply means firing a POST request to a chat API on every single user interaction. In our project's technical guide, this is known as the Naive LLM Anti-Pattern. It shines in a tech demo. But in production, it costs you dearly in money, latency, and reliability. In this article, I reveal the architectural counterbalance we implemented in AI Second Brain: a decision gate that handles everything locally whenever a generative model isn't strictly necessary.

01 · THE PROBLEMThe hidden toll of the naive LLM

Unnecessary Cloud BillsEvery request pays input and output token fees, even when an elementary conditional statement would do the job.
Latency Penalties1.2 to 3.5 seconds per API hop, combining network round-trips and remote token inference, for each user click.
Hallucinations in Business LogicInconsistent responses where only one correct answer should exist, such as approving or declining a financial transaction.
Rate Limits & OutagesHTTP 429 or 503 errors from upstream AI providers bring down entire business workflows if no local fallback exists.

Without Decision Gate (Naive LLM)

“Validate if this tax ID is syntactically valid and format it as 000.000.000-00.”
“Processing... [Invoking GPT-4o: 1,450 prompt tokens + 280 completion. Latency: 1,820ms. Cost: $0.009] The provided ID is valid and formatted.”
“Repeat this verification for our 50,000 users database.”
⚠️ ~86 million wasted tokens, $450 in raw API costs, and 25 cumulative hours of latency for what a local regex checks in 0 ms.

With AI Second Brain & JEV Gate

“Validate if this tax ID is syntactically valid and format it as 000.000.000-00.”
“Intercepted by Deterministic Gate (Tier 1). Local MOD11 checksum executed in 0 ms. 0 tokens consumed.”
“Great. If rejected, draft an empathetic email explaining the registration discrepancy.”
“Classified as Tier 3 (Generation with context). Injecting business rules and invoking LLM in a single controlled call.”
✨ 94% token savings, zero latency on deterministic logic, and AI applied strictly where it drives real value.

02 · THE GOLDEN RULEThree execution tiers, one question before spending tokens

Rule #1 of the architecture strictly prohibits invoking an LLM when deterministic code or rules engines suffice. In practice, every task is categorized before making any network call:

Tier A · DeterministicCalculations, filters, schema validation, regex, automation scripts. Pure code: 0 ms, zero token cost.
Tier B · Decision & ClassificationSelecting between finite options or categorizing events. Rules Engine (JEV): ~1 ms, zero tokens, 100% auditable.
Tier C · Generation & SynthesisProse, documentation summaries, novel code. Here an LLM is appropriately leveraged, always with strict output schema validation.

03 · THE JEV PATTERNIdentify, decide, validate, and only then generate

1 · IdentifyThe system collects strongly-typed application state: request headers, payload fields, numerical thresholds.
2 · DecideA typed evaluation layer returns a discrete categorical choice accompanied by confidence and an audit rationale.
3 · ValidateDeterministic rules verify that the proposed action conforms to business policy before triggering side effects.
4 · Generate (Optional)A generative model is invoked only if synthesizing natural language or freeform prose is explicitly required.

The interface contract is concise and agnostic across any tech stack. In TypeScript:

interface DecisionResult {
  decision: 'PROCEED' | 'REJECT' | 'CLARIFY' | 'ESCALATE';
  ruleId: string;      // auditability and tracking
  confidence: number;  // 0.0 to 1.0
  rationale: string;   // human-readable explanation
}

Consider a practical refund microservice: incoming requests query the local engine first. If the verdict is PROCEED, the refund executes without spending a single token. If ESCALATE, it queues for human review. Only when there is unstructured user dispute text to dissect is an LLM invoked.

04 · REAL PROOFThe project practices what it prescribes

This exact engine powers AI Second Brain itself (scripts/decision-provider.js) synchronously on CPU, 100% offline. In Quickstart Studio, if a developer types an ambiguous instruction, the engine intercepts it prior to calling any model and requests clarification:

> add payments→ CLARIFY · JEV-RULE-AMB-PAYMENT · confidence 0.95

The logged audit rationale is explicit: payment request lacking specified gateway provider or settlement methods. No guesswork, no hallucinations.

05 · AGENT OBEDIENCEHow your IDE agent follows this

LLMs have no personal agenda: they adhere to the context and constraints injected by the workspace. That's why this governance resides in files agents automatically ingest: universal AGENTS.md, the ai-decision-gate skill (5-step triage), and architectural rule 01-ai-decision.md.

Scenario A · Central CockpitWith the AI Second Brain directory open in your editor, governance rules load 100% automatically across Claude Code, Cursor, Windsurf, Cline, and others.
Scenario B · Isolated RepositoryWhen working inside an isolated repo, configure a governance bridge at the root (AGENTS.md, CLAUDE.md, or .cursorrules) referencing these central rules.

07 · PRODUCTION CHECKLISTBefore deploying an AI feature to production

  • Has the task been classified: deterministic, decision, or generation?
  • Have you verified that pure code or SQL cannot resolve the requirement?
  • Does the codebase depend on an IDecisionProvider interface rather than a hardcoded vendor SDK?
  • Does the local rules engine cover all known deterministic edge cases?
  • Do ambiguous requests return CLARIFY rather than inventing assumptions?
  • If the upstream API goes down, does the application degrade gracefully using local rules?
  • Has this architectural decision been recorded in the project's DECISIONS/ log?
Knowing when NOT to invoke an LLM is a core software engineering discipline, not a limitation.
