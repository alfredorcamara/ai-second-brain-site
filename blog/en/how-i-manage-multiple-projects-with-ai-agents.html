How I manage multiple projects with AI agents without losing the thread

Switching projects is expensive, and with AI agents it costs twice: your memory and the agent memory. The thread is the recorded state, not the recollection.

AC
Alfredo R. CâmaraCreator of AI Second Brain
📅 November 2, 2026·⚡ Productivity & Workflow

Anyone who manages several projects knows the feeling of opening a repository and not remembering where they stopped. With an AI agent the problem doubles, because it does not remember either. I call the thread whatever lets you resume exactly where you stopped (as in “losing the thread”): where I stopped, why I decided this way and what I learned. My solution was to take the thread out of both heads and put it in files that both can read.

01 · THE THREADWhat the thread is, and how it breaks

Where did I stop?
CURRENT_STATE.md: active tasks, completed ones and blockers.
Why did I decide this way?
DECISIONS/: the project ADRs, with reasons and alternatives.
What did I learn?
memory/lessons-learned.md: what worked and what is still pending.

02 · TWO PROJECTS, ONE DAYThe same switch, with and without recorded state

Without recorded state

“Morning, payments project: where did we stop?”
“I do not have the context from the last session. Can you explain what has been done?”
“Afternoon, web app: what was that login bug again?”
“I do not know which bug you mean. Can you describe it again?”
⚠️ Two project switches, two rebuilds from scratch.

With recorded state

“Morning, payments project: where did we stop?”
“I read CURRENT_STATE.md: the webhook is done and reconciliation is missing, blocked by the sandbox credential. Start with that?”
“Afternoon, web app: what was that login bug again?”
“I read the web app CURRENT_STATE.md: the login bug is recorded, with the session cookie hypothesis. Resume from there?”
✨ Two resumes in seconds, each in its own context.

Illustrative example conversation.

03 · PARK AND RESUMEWhat to do when leaving and coming back

When leaving (park)
• record the next step and what is blocked
• note the decisions made
• close the session with the session-memory skill or Session Capture
When coming back (resume)
• tell the agent which project you will work on
• ask for the current context: the agent reads PROJECT.md, CURRENT_STATE.md, the decisions and the memories
• check the summary before acting

The full closing ritual and the maintenance cadence (daily, weekly, per sprint and quarterly) are in the Document rot article.

05 · FIVE SITUATIONSOne skill for each moment of the day

Starting work
You tell the agent which project you will work on. It reads the contracts, decisions and memories, and returns an up-to-date summary.
Implementing a feature with AI
The ai-decision-gate skill classifies the task and proposes the architecture before any code. Afterwards, it updates memory and documentation.
Investigating a bug
The bug-investigation skill follows hypothesis, test and root cause, and records the resolution in lessons-learned.md.
Starting a new project
The project-onboarding skill creates the standard structure in projects/<name>/ and fills in the contracts.
Reviewing the architecture
The architecture-review skill checks decoupling, security and resilience, and records the conclusions in a new ADR.

06 · RULES OF THUMBFive habits that hold the thread

  • One session, one project: do not mix contexts in the same conversation.
  • Do not switch projects without closing the session.
  • Leave the next step written down before leaving.
  • What stayed only in the chat does not exist: turn it into state or an ADR.
  • Read the agent summary: it is the bridge, not the final truth.

My own rules of thumb, not project rules.

07 · THE DASHBOARDSee every project at once

To switch, the dashboard shows the connected projects and their governance status. Each workspace has the Overview & Contracts tab, useful for resuming, and the Memory Diagnostics & Health tab, which by its name is the place to check that memory is up to date (check what it shows in your version).

08 · HONEST LIMITSWhat the method does not do for you

The ritual can become bureaucracy
If closing the session costs more than it yields, the method falls out of use. Session Capture reduces the effort.
The agent summary can be wrong
It summarizes what is recorded. If the record is stale, the summary is too.
There is a human limit
The method lowers the cost of switching projects, but it does not fit more projects into your attention.
