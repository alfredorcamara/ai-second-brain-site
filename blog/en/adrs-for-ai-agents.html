ADRs for AI agents: how to stop the AI from undoing decisions you already made

Git shows what changed. Only the ADR records why. That record is what stops the next agent from “cleaning up” an optimization you made on purpose.

AC
Alfredo R. CâmaraCreator of AI Second Brain
📅 November 2, 2026·⚡ ADRs & Governance

Imagine that three weeks ago an agent replaced a LINQ query with Dapper to gain performance. Today a new session looks at the code, finds the choice odd and “cleans” it all back. Nobody erred on purpose: the agent simply did not know why. Git shows what changed. The ADR keeps the why.

01 · THE PROBLEMThe good intention that undoes your decision

Without an ADR

“Can you clean up the data layer? There are a lot of hand-written queries.”
“Sure! I will replace Dapper with stored procedures with Entity Framework, which is more modern and readable.”
“…that was on purpose. Performance tanked.”
⚠️ The optimization was undone with good intentions.

With an ADR

“Can you clean up the data layer? There are a lot of hand-written queries.”
“Before touching it, I read DECISIONS/ADR-002-dapper-stored-procedures.md: we use Dapper for performance and legacy compatibility. I will keep it. Should I propose improvements within that decision, or open a new ADR to revisit it?”
✨ The decision was respected and the path to change it is clear.

Illustrative example conversation; the ADR file name is fictional.

02 · THE ADRThe record of why, in a file the agent reads

In AI Second Brain, each project keeps numbered ADRs in DECISIONS/ (such as ADR-001-stack-inicial.md), and global decisions live in decisions/GLOBAL_DECISIONS.md. The master rule requires the agent to consult those decisions before changing any pattern.

# ADR-002 · Dapper with stored proceduresStatus: acceptedContext: high query volume and legacy compatibility.Decision: use Dapper with stored procedures in the data layer.Rejected alternatives: Entity Framework (performance cost in this scenario).Consequences: more hand-written SQL, predictable performance.Rule for agents: do not replace without explicit authorization and a new ADR.

Suggested template, written by me. The project does not enforce a format.

03 · HOW THE AGENT USES ITConsult before changing

New task→Master rule: consult DECISIONS/→Is there an ADR on the topic?→Yes: respect it or propose a new ADR→No: proceed and record

04 · CHANGING YOUR MINDAn immutable decision is not an eternal decision

Immutable means the ADR is not rewritten to erase the past. When reality changes, the path is a new ADR, and the project rule is not to change the architecture without recording it. Marking the old one as superseded is a practice I recommend.

05 · LEGACY PROJECTSRetroactive ADRs: shielding what already exists

In legacy code the biggest risk is the agent trying to “rewrite everything” with modern patterns, such as swapping Dapper for Entity Framework or SQL Server for PostgreSQL. The defense is recording retroactive ADRs for the decisions that must not be violated, also stating who can authorize an exception.

Read the [NAME] project and list the architecture decisions already consolidated.For each one, write a retroactive ADR in DECISIONS/ with the reasonand the rule: do not change without explicit authorization.

Example prompt, written by me.

06 · CHECKLISTBefore ending the session

  • Every relevant architecture decision became an ADR.
  • No decision stayed only in the chat.
  • The ADR records the reason, rejected alternatives and consequences.
  • The master rule says to consult DECISIONS/ before changing a pattern.
  • A pattern change produced a new ADR, and the old one was marked as superseded.
  • The agent knows who can authorize an exception.

07 · HONEST LIMITSWhat the ADR does not solve

It is not a technical lockIt is context the agent reads. It depends on the IDE loading the rules: in an isolated open repository you need a bridge file (AGENTS.md, CLAUDE.md or .cursorrules).
Too many ADRs become noiseRecord the decisions that would change the project course, not every implementation detail.
A stale ADR misleadsIf reality changed and the record did not, the brain rots. Update or supersede it.
