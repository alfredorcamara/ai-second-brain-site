Autonomy & Documentation · 5 min read

An autonomous lab that writes your project's technical documentation on its own.

How to turn scattered AI conversations into enduring, two-layer versioned knowledge synchronized in Markdown files.

AC
Alfredo R. Câmara Creator of AI Second Brain
📅 October 05, 2026 · ⚡ AI Second Brain Research Lab

Every development team has lived this: a complex technical topic requires research, someone spends hours in a chat with an LLM, and the entire outcome stays trapped in an ephemeral browser tab that no one will ever find again. The Research Lab in AI Second Brain was created to turn these ephemeral conversations into versioned knowledge organized in Markdown files directly inside the project repository. You define the topic, and the autonomous engine takes over research, structuring, and cataloging.

01 · HOW IT WORKSFrom question to versioned repository file

Execution Flow 1. Free topic prompt → 2. AI aligns context with PROJECT.md → 3. Subtopic decomposition → 4. .md file generation → 5. 3D graph & live memory

The key differentiator is architectural context: before starting research, the AI reads the project's core contracts and aligns the briefing with the real constraints and goals of that ecosystem. That's why research output is immediately tailored to your stack and conventions, rather than generic like a standard web search.

02 · TWO LAYERSKnowledge on one side, action on the other

📘 knowledge/ The what and why: foundational concepts, state of the art, industry benchmarks, and trade-off analysis. Example: mathematical foundations of the ELO algorithm, event-driven architecture concepts.
🛠️ actionable/ The how to apply: practical technical specifications, executable schemas (SQL Server, Prisma, PostgreSQL), TypeScript/Node.js controllers, and test suites. Example: ELO calculation implementation and API routes.
projects/<project>/RESEARCH/<topic>/ ├── _meta.json # status and Living Prompt history ├── OVERVIEW.md # executive summary and topic roadmap ├── knowledge/ # layer 1: what and why │ ├── fundamental_rules.md │ ├── state_of_the_art.md │ └── comparative_analysis.md └── actionable/ # layer 2: how to apply in the project ├── proposed_architecture.md ├── suggested_schema.md └── business_rules.md

03 · LIVING PROMPTThe research definition evolves with you

The definition of a research job isn't a static one-liner. You can refine intent at any moment or click “Enhance with AI”, which suggests refinements based on the current project governance state. Each iteration is audited and logged in the _meta.json file:

Living Prompt Evolution v1 · developer's raw intent → v2 · refined by AI based on architecture → v3 · focus and scope tuned by you

In subsequent runs, history is compared to flag contradictions, new discoveries, or needed addenda without losing previous versions. In the web interface, a “Before vs After” diff view allows accepting or tweaking suggestions before approval.

04 · THE ENGINEEngineered not to break midway

Deep, comprehensive research frequently hits tokens-per-minute (TPM) limits, timeouts, and network drops. The engine (research-engine.js integrated into the unified AI gateway) was engineered to handle these issues resiliently without bloated third-party dependencies, relying solely on native Node.js modules:

✓ knowledge/fundamental_rules.md ✓ knowledge/state_of_the_art.md ⏸ [RATE LIMIT] Dynamic backoff requested by provider + 2s buffer ✓ knowledge/comparative_analysis.md (retry 1 succeeded) — [SESSION INTERRUPTED BY USER AND RESUMED] — ↻ fundamental_rules.md already exists on disk: skipped (0 tokens) ✓ actionable/proposed_architecture.md
Rate limits under control Catches HTTP 429, computes server-specified pause time, adds a 2-second preventive buffer, and intelligently retries up to 3 times.
Instant job resumption When restarting an interrupted job, checks physical disk files and skips already synthesized topics, safeguarding your budget.
Real-time progress streaming A continuous Server-Sent Events (SSE) feed powers progress bars and live logs in the user interface.
Defensive outputs & fallbacks Aggressive markdown sanitization for reliable schema extraction, paired with automatic provider failover during outages.

05 · INTEGRATIONKnowledge made immediately visible

At the end of the research cycle, the engine compiles everything into a master index (OVERVIEW.md) complete with relative navigable links. Automatically, these new artifacts are ingested by the 3D Neural Graph, receiving distinct nodes and color coding per thematic layer. On the dashboard, Research Lab features a dedicated workspace view with research cards, prompt audit trails, and direct shortcuts to the local file explorer.

06 · FOR BUILDERSThe API powering the engine

All this automation operates on lightweight, decoupled REST endpoints, enabling external tools or custom automation scripts to plug directly into the research pipeline:

API Route Responsibility
POST /api/ai/refine-prompt Refines user intent combining PROJECT.md and ARCHITECTURE.md
POST /api/ai/decompose Decomposes topic into balanced knowledge and actionable subtopics
POST /api/projects/:name/research Scaffolds physical lab structure in local file system
POST .../research/:slug/definition Updates research definition with incremental revision tracking
POST .../research/:slug/run Triggers autonomous generation engine with SSE progress stream
GET .../research/:slug/status Queries real-time status of the executing research pipeline

07 · HONEST LIMITSTreat as technical drafts

Content synthesized by language models demands critical engineering review. Research Lab dramatically accelerates exploration and establishes structured documentation, but the responsibility of adopting a pattern, approving a schema, or validating business rules remains with the developer — and should be formalized in an Architectural Decision Record (ADR).
