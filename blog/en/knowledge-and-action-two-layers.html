Knowledge and action in two layers: how to organize technical research for AI agents

How decoupling technical research between knowledge/ and actionable/ avoids the “Lost in the Middle” syndrome and converts raw theory into production-ready code.

AC
Alfredo R. Câmara Creator of AI Second Brain
📅 October 10, 2026 · ⚡ Research Lab & Architecture

Technical research typically ends up trapped inside a sprawling markdown document that blends theory, editorial opinions, and raw code snippets. For a human engineer, parsing it is exhausting. For an AI agent constrained by token windows and vulnerable to the “Lost in the Middle” effect, it is fatal: the model must churn through hundreds of paragraphs just to extract the specific parameters needed for an immediate task. The architectural remedy in AI Second Brain is decoupling research into two distinct layers: one dedicated to timeless knowledge, and the other to actionable implementation.

01 · THE CORE IDEATwo distinct questions, two dedicated locations

Every technical topic answers two fundamentally different questions: “What is this and why does it work this way?” versus “How do I apply this to my exact tech stack?”. Each question belongs in its own directory, bridged cleanly by a formal Architecture Decision Record (ADR).

03 · A CONCRETE EXAMPLEFrom theoretical math to concrete API endpoint

Consider technical research exploring an ELO matchmaking ranking engine. The knowledge layer houses mathematical distribution formulas. The actionable layer contains concrete TypeScript calculation algorithms, database schemas, and Express route controllers. In between, an immutable ADR records why ELO was selected over TrueSkill.

04 · CLASSIFICATION TESTSThree quick heuristic checks

Whenever you or your agent wonder where a snippet belongs, apply these quick litmus tests:

  • If I changed the programming language or framework tomorrow, would this text remain 100% valid? If yes, it belongs in knowledge/.
  • Could an AI agent implement the feature directly without asking any clarifying questions? If yes, it belongs in actionable/.
  • Does it explain why we chose Option A over Option B? If yes, that trade-off belongs in an ADR.

05 · HOW AGENTS INGESTLaser-focused context, auditable sources

Incoming Technical Query Ctrl+K: Ask the Brain → BM25 / TF-IDF Ranking → 5 to 7 Prioritized Files → Answer with Clickable Citations → Up to 12 Sources on Demand

The hybrid search prioritizes governance documents (ADRs at 2.4x, active state at 2.2x, contracts at 2.0x, rules at 1.8x) and injects only the most relevant 5 to 7 primary documents into working context. When research concludes, an OVERVIEW.md indexes all topics, and the 3D graph renders distinct node glyphs for each layer.

06 · FROM THEORY TO PRODUCTIONThe end-to-end pipeline

Recommended Workflow Research → knowledge/ → ADR Record → actionable/ → Source Code → Session Memory

Research informs but never unilaterally commits code. Knowledge provides background, the ADR codifies architectural decisions, the actionable layer translates logic to your current framework, and session capture synchronizes project state.

07 · PITFALLSWhat can go wrong

Action Without Contracts If PROJECT.md and ARCHITECTURE.md are vague, the actionable layer defaults to generic boilerplate. Quality actionable outputs require rigorous contracts.
Knowledge as Dead Encyclopedia If nobody references or consults the knowledge layer, it becomes digital hoard. Periodically prune and archive superseded topics.
Unreviewed AI Claims Agent research outputs are technical drafts. Always verify critical performance claims and security assumptions before shipping.
Stale Research Frameworks evolve rapidly. Archive out-of-date research to protect your agent from recommending deprecated API methods.
