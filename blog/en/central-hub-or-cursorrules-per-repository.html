Central hub or .cursorrules in every repository? The debate for anyone with more than one project

Putting .cursorrules, AGENTS.md or CLAUDE.md at the root of each repository is a legitimate approach. The question changes when you have more than one project.

AC
Alfredo R. CâmaraCreator of AI Second Brain
📅 November 2, 2026·⚡ Architecture & Governance

Every senior developer asks this: why not put AGENTS.md, .cursorrules or CLAUDE.md straight at the root of each project? For a single project it is a great answer. The debate heats up when you switch between several products and want all of them to follow the same standard.

01 · THE DEBATETwo ways to give rules to an agent

02 · THE CRITERIAFour questions that decide

Rule portability
In the repository: copy and paste between projects.
In the hub: global rules in one place.
Versioning with the code
In the repository: perfect, rules and code in the same Git.
In the hub: requires syncing state between satellite and hub.
Portfolio view
In the repository: nonexistent.
In the hub: the dashboard and the projects/ folder show every project.
Secrets and IP isolation
In the repository: business notes may end up in a public repository.
In the hub: they stay in the private brain.

03 · HOW THE HUB WORKSCode stays in the satellite, knowledge in the hub

The hub holds the rules, skills, knowledge, memory and each project folder. Each satellite repository (API, web, mobile) keeps its code, CI/CD and Docker, and connects to the hub through an NTFS junction or directory symlink, without duplicating files.

Open the hub in the IDE→The agent reads rules and skills from the hub→Reads state in projects/<name>/→Works on the project→Logs the session in the hub

04 · TWO SCENARIOSCentral cockpit or isolated repository

Scenario A · Central cockpit
With the hub folder open in the IDE, governance loads automatically, with nothing to configure in each repository.
Scenario B · Isolated repository
If you open only the repository, it needs a governance bridge at the root (AGENTS.md, CLAUDE.md, GEMINI.md, .cursorrules, .windsurfrules, .clinerules or copilot-instructions.md) pointing to the same rules.

05 · WHICH TO CHOOSEA rule of thumb for each side

Choose the hub if…
• you manage several products
• you want the same standard across all
• you need a portfolio view
• you keep business notes private
Keep rules in the repository if…
• you have a single monolith
• your team is large and already organized in the repository
• you prefer versioning everything together

You can also combine them: the hub as the source and the bridge files in the repositories as generated copies. Each repository keeps working on its own, and the rules come from a single place. This combination is my recommendation, and the project does not enforce it.

06 · HONEST LIMITSThe price of the hub

One extra step
You need to open the hub in the IDE or keep bridge files in the repositories.
State to keep in sync
Project state lives in the hub. If the code moves ahead and the record does not, the brain rots.
Not for everyone
For a single project, the structure may be more than you need.
