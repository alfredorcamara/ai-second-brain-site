0 ms and zero cost: the tasks you shouldn't send to an AI

The most valuable question in AI development isn't “which model should I use?”, but “do I need a model here?”.

AC
Alfredo R. Câmara Creator of AI Second Brain
📅 October 22, 2026 · ⚡ AI Decision Gate & JEV

The most valuable question when developing with AI is not “which model do I use?”, but rather “do I even need a model here?”. Many tasks given a prompt could easily be solved by a single line of code, a business rule, or a local classifier in zero milliseconds at zero token cost. I’ve compiled the practical checklist we use at AI Second Brain to decide what not to send to an AI.

02 · THE CHECKLISTTasks that never need an AI

Form validation, tax calculation, auth rules Zero room for interpretation: the answer is exact and deterministic. Use: Pure C# or TypeScript code: zero cost, total determinism
Calculations, filters, regex, and file scripts Any task without semantic ambiguity belongs strictly in Tier A. Use: Pure code: 0 ms, zero token cost
Classifying SQL job failure severity Picking among finite operational categories is classification, not generation. Use: JEV: ultra-fast, zero tokens, fully auditable
Detecting transaction volume anomalies The statistical pattern is mathematically predictable. Use: Statistical algorithm with sub-millisecond latency
Intercepting vague requests like “add payments” Identifying missing payment providers and methods to ask for clarification. Use: RulesDecisionProvider returning CLARIFY with 0 tokens

03 · THE COUNTERPOINTWhat truly deserves a model

Natural language diagnostics Explaining why an intricate batch job failed by contextualizing stack traces. Requires open-ended reasoning.
Customer support chatbots Conversational responses backed by a living knowledge base via LLMs with RAG in the AI Gateway.
Generation and synthesis Prose, architectural documentation, and novel code. Tier C, always with rigorous output validation.

04 · IN PRACTICEThe workflow that spends tokens only when needed

Refund Request Flow Local Engine (0 ms) → PROCEED: executes refund → ESCALATE: human auditor queue → Only freeform text: calls LLM

The application queries the local engine first. The vast majority of known cases resolve immediately on-device, without network trips or token consumption. The LLM becomes the exception, not the rule.

05 · INFRACTIONSWhat the architecture explicitly forbids

  • Using an LLM for deterministic logic or mathematical calculation.
  • Calling generative AI inside tight processing loops or recurring jobs.
  • Bypassing the AIJev pattern when the task is pure decision or classification.

Already have a pipeline invoking a model on every HTTP request? Here is the refactoring prompt suggested in our architectural guide: 

Analyze the file [path/to/file].
It currently calls an LLM on every incoming request.
Refactor using the AI Decision Gate & JEV pattern:
- extract a local RulesDecisionProvider for frequent cases (0 ms);
- retain the LLM as a fallback or for the CLARIFY decision;
- maintain unit tests for the local engine without network mocks.

06 · RULE OF THUMBHow to tell if you're overusing AI

A personal heuristic: if you can write a unit test with the exact expected output asserting against a fixed value, you almost certainly do not need an LLM. Our technical guide points to up to 70% of requests resolved locally in predictable workflows. Treat this as a benchmark and measure your domain, because the savings scale directly with how repetitive your traffic is.
